## 2. 固有代价（登记即可，不阻塞）

| # | 愿景条目 | 代价 | 已留的扩展位 / 缓解 |
|---|---|---|---|
| **S2** | §3.10 云同步（坚果云 / WebDAV） | **目录名参与语义**：改一次标题 = 改一次路径，网盘客户端多半按"删 + 建"处理 → 该记录目录下的媒体会被重传。（Obsidian + 网盘是同一个痛点） | `entry.json.id` 与 `MediaMeta.hash` 都不变 → 将来的同步引擎能识别"同一实体换了路径"，可做增量 |

| **S5** | §3.10 E2E 加密 **vs** §3.8 Obsidian 联动 | 两条**互斥**：正文加密后 Obsidian 打不开、文件也不再"可读可改" | 现在不动。真做加密时，布局上加"密文形态"（如 `note.md.age`）即可容纳 —— **前提是扫描按"正文文件名"认、不写死扩展名** |

| **S9** | §3.10 版本历史 / §3.7 相册迁移 | ——（**正面**） | `note.md` 是单一 Markdown 文件，Git / 网盘 / 任何工具都能直接做版本；v1 把正文藏在 UUID 目录的 JSON 里做不到 |
| **S10** | §3.11 多端、§3.1 打开即写 | ——（**正面**） | ①CM6 更适合移动端 WebView（Obsidian 手机版就是它：视口渲染、无 DOM 结构改写、移动端实测过得去），换引擎对"移动端复用同一套 WebView"是加分（**更正**：原稿写的"体积更小"不成立 —— 实测编辑器 chunk 349.6 → 500.5 KB、gzip 107.4 → 174.2 KB，主包基本不动，见 CM6 提案 §13）；②"编辑器挂载即聚焦"是一行 `view.focus()`，接口留给"打开即写 + 自动保存"那一轮 |

## 3. 核过没问题的一处

VISION §3.4 的"升级链路"（随心记 → 深入记录，可能换场景）在 v2 里 = **记录目录整体 `rename`**。
`fs::rename` 是同卷元数据操作，**几 GB 媒体也是毫秒级**，不涉及复制 —— 所以 v1 那条刻意设计
"换归属 = 改 meta 里的 `entry_id`、不移动几 GB 的文件"（`vault/media.rs` 文件头注释第 2 条）
的初衷（省掉几 GB 拷贝）**依然成立**；要付的唯一代价是 S2 那条（同步工具眼里是一次移动）。
