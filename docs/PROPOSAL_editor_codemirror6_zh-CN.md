> **状态：已实施（2026-09-23 当天完成），落地的偏差见文末 §13。**
> 本文是迁移设计存档；与 AGENTS.md / ARCHITECTURE_IMPL 冲突时以它们为准（它们已同步）。
> 第二轮补齐：v1 范围修正、实现细节（视口 / 露出粒度 / IME / keymap / 滚动 / widget 身份）、
> 文档同步清单、可自动化的验证判据、分步实施、与 VISION 的关系。
> **第三轮：拍板「编辑样式与 Obsidian 完全对齐」为验收标尺（§5.1），并砍掉粘贴侧的格式转换 ——

## 1. 背景：为什么现在的效果"局限"

用户反馈：不要"块级源码盒子"这种特效、不要选中范围被缩小，要 Typora / Obsidian 那种即时渲染、随心编辑。
根因是**引擎选型**，不是实现质量：

| | Obsidian / Typora | 现行（ProseMirror 经 Milkdown） |
|---|---|---|
| 编辑器内核 | CodeMirror 6（Obsidian 就是它） | ProseMirror |
| 文档本质 | **就是纯文本**，源码永远在文档里 | 结构化节点树，`**` 是 mark、语法字符不存在于文档 |
| "渲染" | 给语法符号加装饰**藏起来**；光标所在处摘掉装饰即露出源码 | 渲染态与源码态是两份表示，切换必须序列化/解析翻译 |

现行 Live Source（块级文本化切换）是提案时选的保守路线：整块翻面成 textarea 盒子、选区被关在控件里、
120ms 延迟 —— 这些是**方案的结构性上限**。三条路线对比：

| 路线 | 手感上限 | 代价 | 结论 |
|---|---|---|---|
| **A. 换 CodeMirror 6 内核** | ★★★★★ 真·Obsidian 同款 | 放弃 Milkdown、重写内核与粘贴管线、改 AGENTS 契约 | **已拍板** |
| B. 留 PM 做行内显隐装饰 | ★★★☆☆（70-85%） | 在 PM 里重造 CM6 装饰系统，边界情况极多 | 弃 |
| C. 打磨现有块级方案 | ★★☆☆☆ | 小改动 | 弃（仅作过渡应急手段） |

## 2. 目标与不变量

- **目标**：源码即真值，语法符号用装饰藏/显，光标所在处露出源码；没有盒子、没有层切换、选区永远贯穿全篇。
- **不变**：`MarkdownWysiwyg` 组件 props（value 进 / markdown 字符串出）、`React.lazy` 按需加载、
  磁盘格式、只读渲染器 `MarkdownView`、表单控件 `MarkdownField`、写作台接线。
- **对外承诺也不变**：`docs/theme-contract.md` 只承诺 `.md-wysiwyg` 这一个壳类名，并明确写着
  "`.milkdown` / `.ProseMirror` 不算承诺" —— 所以换内核**不破坏对主题作者的承诺**，改的只是那句括号
  （第三方内部类名从 `.milkdown`/`.ProseMirror` 换成 CM6 的 `.cm-*`）。
- **`MarkdownField` 本轮不动**（它是"表单字段"，看得见源码本来是对的）。已知后果：普通日记 / 旅行 / 挑战
  三个主题的正文**仍是 textarea + 工具栏的源码形态** —— 与写作台会是两种手感，等用过新编辑器再决定是否一起换。

## 3. 依赖变化

- **新增**：`@codemirror/state`、`@codemirror/view`、`@codemirror/language`、`@codemirror/lang-markdown`
  （依赖 `@lezer/markdown`）、`@codemirror/commands`。全 MIT。
- **移除**：`@milkdown/kit`、`@milkdown/react`（已核实全仓只有 `MarkdownWysiwyg.tsx` 引用；
  `src/markdown/parse.ts` 的 remark 属只读渲染侧，不动）。连带消失的还有 prosemirror 家族与 `dompurify`
  （它由 Milkdown 带入，是依赖树里唯一的非宽松许可证项）。
- **不用** React 包装库（`@uiw/react-codemirror` 之类），直接用原生 API。
- **`docs/REFERENCES.md` 的许可证登记表要同步**（AGENTS §1 要求"引入新依赖前先登记"）：
  撤下 Milkdown / prosemirror 几行，登记上面这组 CM6 包。
- **`vite.config.ts` 不用改**（已核：里面没有针对编辑器的 `optimizeDeps` / `manualChunks`）。

## 4. 实现要点

1. `EditorView` + markdown 语言 + **自写 live-preview 装饰插件**（语法符号文本一直在文档里，装饰决定藏不藏；
   光标所在处按 selection 重算装饰、露出源码）。
2. 装饰**只算视口**：语法树遍历用 `view.visibleRanges` 限定范围（配 `syntaxTree(state).iterate({from, to})`）。
   不做这条，千行文档每动一次光标就要全量遍历 —— 性能目标当场落空。
3. 露出源码的**粒度分两种**（Obsidian 的真实行为，写错就是"整行全是源码"或"永远看不见 `**`"）：
   - **块级记号**（`# `、`> `、`- `、`1. `、围栏）→ **行级**露出：光标在该行任意位置就露。
   - **行内记号**（`**`、`*`、`~~`、`` ` ``、`[](…)`）→ **令牌级**露出：光标落进那段令牌的范围才露。
4. 粘贴：**只认纯文本**（CM6 里文档就是 markdown，粘进来的 `#` / `-` / `>` 当场就是渲染好的样子，
   旧 `handlePaste` 那一摊问题消失；也不做任何格式转换、不引转换依赖）。
   **粘贴进来的 `\r\n` 归一成 `\n`**，否则 `note.md` 会出现混合行尾。
5. 复制：CM6 原生复制即 Markdown 文本（旧 clipboard 插件的能力免费获得）。
6. `onChange`：`updateListener` 防抖发 `doc.toString()`；外部换篇与 `emitted` 比对后整体替换
   （现有的"只在外部换了内容时回灌"防打架模式平移 —— AGENTS §9 那条坑对任何编辑器都成立）。
   外部整篇替换时**把滚动重置到顶部**；其余改动不跳。
7. IME：CM6 原生 composition；**组合期间跳过装饰重算，并在 `compositionend` 后补算一次**
   （只跳过不补算的话，拼音打完那行会一直停在源码态）。撤销走 CM6 原生 history（按时间分组，与标准文本编辑器一致）。
8. keymap 要显式列清单：`defaultKeymap` + `historyKeymap`（`Mod-z` / `Mod-y`）+ `markdownKeymap`
   （回车续列表、`Mod-b` 等）+ **`indentWithTab`**（不绑的话 Tab 被焦点吃掉，列表没法缩进）；
   搜索面板 / 自动补全**不开**。
9. 删除全部 Live Source 状态机代码（被引擎原生能力取代）；当时未提交的那点旧实现改动随全量重写一并丢弃。
   **`looksLikeMarkdown` 一并删掉** —— 全仓只有 `MarkdownWysiwyg.tsx` 在用它（已核），换引擎后是死代码，
   按 AGENTS §10「不许为将来留东西」清掉，同时改掉 AGENTS §6/§9 里提到它的两处措辞。
   （原稿写"保留给只读渲染侧"不成立：只读侧走的是 `parseMarkdown`。）
10. CSS 重写：cm 主题化全部走 `--fv-*` token，标题 / 引用 / 列表视觉与只读渲染器对齐。
    **滚动与尺寸要继承 `.ProseMirror` 现在那几条约定**：`min-height: 320px` / `max-height: 70vh` /
    `overflow-y: auto` + **`overflow-x: hidden` + `scrollbar-gutter: stable`**
    —— AGENTS §9 那两条"滚动条抖动"坑原样适用（长行不换行时会触发横向↔纵向互相激发）。
11. **widget 身份要稳**：CM6 的 `WidgetType.eq` / `toDOM` 与 PM 同类 —— 身份不稳会把 DOM 拔掉重插
    （表现是丢焦点 / 光标跳）。表格、图片、分隔线这些替换型 widget 都要按这条写。

## 5. v1 渲染清单

| 节点 | 不在光标处 | 光标在处（露源码） |
|---|---|---|
| 标题 `#`~`######` | 行样式（字号 / 粗细与只读渲染一致），`#` 隐藏 | 行级露出 `# ` |
| 引用 | 行样式（左侧竖线 / 灰字），`> ` 隐藏 | 行级露出 `> ` |
| 无序 / 有序列表 | 缩进 + 项目符号替换，标记隐藏 | 行级露出 `- ` / `1. ` |
| 任务列表 | 勾选框（只读渲染） | 行级露出 `- [x] ` |
| 分隔线 | 替换成 `<hr>` | 行级露出 `---` |
| 粗体 / 斜体 / 删除线 / 行内码 | 样式装饰，记号隐藏 | 令牌级露出 `**` `*` `~~` `` ` `` |
| 链接 | 只留文字（可点） | 令牌级露出 `[文字](url)` |
| 围栏代码块 | 按代码块排版，围栏隐藏 | 行级露出围栏与语言标注 |
| 图片 `![alt](url)` | **仅 http(s) / data** 渲染成图；本地路径按文本 | 令牌级露出源码 |
| 表格 | **替换成只读表格**（真表格行列，不是管道符文本） | 行级露出管道符（整块可编辑） |

### 5.1 与 Obsidian 对齐的验收清单

**这是"完全做成和 Obsidian 一致"的落地口径**，实施与验收都按这张表逐条对。

排版与结构（v1）：

- 块间距节奏、行高、正文观感与只读渲染器 `MarkdownView` 一致（同一段文本两边看起来要是同一个东西）。
- 列表：项目符号（`•` / 数字）、子项缩进、续行对齐；**回车自动接着上一项的标记**（`- ` / `1. `）；
  Tab 缩进、Shift-Tab 反缩进。
- 任务列表：`- [ ]` 渲染成勾选框，点一下切换 `[ ]` ↔ `[x]`（改的还是文本本身）。
- 引用：左侧竖线 + 灰字；连续多行归在同一块引用里。
- 代码块：围栏收起后按代码块排版（等宽 + 底纹 + 圆角），语言标注仍可编辑。
- 表格：表头底纹、列对齐（`:---` / `:---:` / `---:`）、发丝线边框。
- 分隔线：`---` 渲染成一条线。
- 行内：粗体 / 斜体 / 删除线 / 行内码样式与只读渲染器一致；链接用 accent 色、**不带下划线**。
- 裸 URL 渲染成可点链接。
- 光标：细竖线；选中是一块连续背景，**能跨任意块拖动**（没有盒子、不换字体）。
- 连续空行原样保留（Markdown 里空行有意义，不吞行）。

行为（v1）：

- 打字即渲染：打 `# ` 这行当场变标题（不是"变成节点"，是文本立刻按标题渲染）。
- 光标移开 → 记号立刻收起；移回来 → 立刻露出。无延迟、无层切换、无盒子。
- `Mod-z` / `Mod-y` 撤销重做（按时间分组，跟标准文本编辑器一致）。
- 输入法组合期间不动装饰，组合一结束立刻补算。

**颜色 / 字号 / 圆角 / 阴影仍走 `--fv-*` token**（AGENTS 铁律：组件里零裸色值，三套外观预设骨架必须一致）。
所以"与 Obsidian 一致"落在**结构与行为**这一层；若想连观感也贴近 Obsidian，那是**外观预设**的活
（单独调一套配色 / 字号），不该焊死在编辑器里。

## 12. 与「自动保存 / 右键删除」的关系

按本提案办：**本轮只换内核**，自动保存与右键删除紧随其后一轮（那两条产品愿望已登记：
保存按钮取消改自动保存本地；编辑器内删除按钮取消、改左侧文件列表右键弹出删除）。

自动保存那一轮有一条**必须先处理的回环**：写作台原来会在 `updatedAt` 变化时重载草稿，
自动保存会让它变成"存一次 → 重载一次草稿"，打字快时可能把刚敲的字冲掉。

> **2026-09-23 已实施**（见 `WritingScene.tsx`）：重载草稿的依赖**只认"哪一篇"**，
> 不再跟 `updatedAt`；加上"停手 600ms 写一次 + 切篇 / 窗口失焦 / 卸载时补写"，
> 待写的那一份连同"是哪一篇"一起存在 ref 里（所以切篇后补写也写得对）。
> 删除按你说的改成了**右键菜单**（`EntryMenu`，公共件）—— 触摸屏没有右键，用**长按 500ms** 兜底，
> 鼠标指针不进长按计时（免得误触）。
做法：记住"我最后写给磁盘的那份文本"，重载时比对，自己写的就跳过。

## 13. 实施结果与偏差（2026-09-23 落地）

**落地文件**：`features/scene/markdown/MarkdownWysiwyg.tsx`（组件 + 视图 + 键位 + 结构性样式）
与 `features/scene/markdown/livePreview.ts`（实时渲染装饰层），样式进 `MarkdownWysiwyg.css`；
`src/markdown/parse.ts` 删掉 `looksLikeMarkdown`（只留只读渲染器用的 `parseMarkdown`）。
按 §11 的建议**拆成两个文件**，AGENTS §1 / §6 与 theme-contract 的括号一次性改全。

**与计划不一致的地方（实施中发现）**：

1. **装饰必须拆成两半**。计划里"一个装饰插件"不成立：CM6 抛
   `RangeError: Block decorations may not be specified via plugins`，而且**整块不渲染** ——
   画面全空、DOM 里文字俱在，从症状上看不出是装饰的问题。
   现在 `outer`（行级类名、整块 widget、表格）走 `StateField` + `EditorView.decorations.from`，
   `inner`（行内记号与 widget）留在 `ViewPlugin` 里、只遍历 `view.visibleRanges`。
2. **块级替换（`block: true`）不能用**。它会吞掉整行，**连带把相邻行的行级装饰一起丢掉**：
   围栏变成"没样式"，表格 widget 干脆不落地。改成：围栏只藏围栏**文本**、整块铺代码底色；
   表格改成**行内**替换（代价：表格后留两行空行，v1 接受）。
3. **露出源码的粒度由"宿主块"决定，不看记号自己**。围栏上下两条 `CodeMark` 各自与光标比较时，
   光标停在代码正文里两条都不露 —— "光标进块显示源码"当场失效。块级记号一律
   `rangeTouched(parent.from, parent.to)`，行内记号才按令牌自身范围判。
4. **结构性样式写不进 `@layer`**。CM6 往 document 注入的基础样式是**未分层**的，
   层叠层规矩里未分层永远压过分层 —— 写多少条都不生效。滚动容器 / 内边距 / 光标 / 字号
   挪进 `EditorView.theme({...})`（值仍是 `--fv-*`），装饰类名照旧留在 CSS 文件里。
5. **包体是涨的，不是降的**：主包 417.68 KB（几乎不动），编辑器 chunk **349.6 → 500.68 KB**
   （gzip 107.4 → 174.14）。原因是 `lang-markdown` 会带进 `lang-html`，而可选的
   `markdownKeymap` 正需要它（Enter 续列表 / Backspace 拆记号）。选择保留它、不手写这套命令——
   手感与正确性优先于 150 KB 的按需 chunk。**上面 §1 表格里"体积更小"的说法作废。**
6. **粘贴按拍板只认纯文本**：文档就是 Markdown 文本，纯文本原样插入即当场渲染，
   自写的判据、解析转换、`dompurify` 全部不需要。**已知回退**：从浏览器复制的带格式内容只剩文字。
7. **验证换到了真浏览器**：App 窗口收不到合成的键盘事件（连普通 `<input>` 都收不到），
   于是临时用 vite 挂一个 harness 页，在浏览器里逐条验（进出源码态、行内记号藏显、打字、
   Ctrl+Z、Ctrl+B、粘贴、十几行到 1200 行的虚拟化与延迟），再回 App 确认挂载与主题集成。
   **未能验证**：真实输入法（IME）的组合行为只有"`composing` 期间不重算装饰、`compositionend` 后补算"
   这段代码保证，没有在真输入法下实测。

**§5.1 的 Obsidian 对齐清单**：11 条排版项与 4 条行为项全部落地（标题字号层级、引用左条、
列表圆点、任务勾选框、代码块底色与首尾圆角、分隔线、表格表头与对齐、链接点缀不underline、
行宽与内边距按编辑器自身、Enter 续列表 / Backspace 拆记号 / Tab 缩进 / 常用行内快捷键）；
配色与尺寸仍全部走 `--fv-*`，未为对齐 Obsidian 写任何裸值。
