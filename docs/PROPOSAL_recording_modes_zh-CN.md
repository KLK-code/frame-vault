# 提案：题材、记法、记录 —— 外面套一层（讨论稿）

> **状态：讨论稿（2026-09-23，同日第二轮）。** 这一轮**只写文档、不动代码**。
> 第二轮的变化：题材改成**在现有结构外面套一层目录**（第一稿想的是动记录层加一个"记法"标记，
> 那一步更重、且不是必须的）。结论没拍死的地方都在 §7，每条给了选项与我的建议。
> 与 AGENTS.md / ARCHITECTURE_IMPL 冲突时以它们为准（它们描述的是**当前**实现）。

## 1. 一句话

**题材 = 现有结构外面套的一层目录**（科研、旅游、挑战……），用途是**归类、打标签、在资源管理器里管文件**；
**里面的一层原样不动** —— 现在的一个文件夹（= 一个文件夹 + 绑定的主题）仍然是"这一类记录怎么记"的单位。

所以：**磁盘上多一级目录；记录层、正文 `note.md`、媒体、命名模板、记法全都不动。**

## 2. 目标布局

```text
<用户选的目录>/
├── vault.json                      身份文件（layout 不变）
├── .framevault/trash/<原目录名>/    回收站
├── 科研/                            ← 新的一套：题材（一级目录）
│   ├── 论文笔记/                     ← 内层：现在的"文件夹 + 绑定主题"，原样不动
│   │   ├── folder.json
│   │   └── 2026-09-23 周报：第一次消融实验/
│   │       ├── entry.json
│   │       └── note.md
│   └── 实验打卡/
│       ├── folder.json             ← 绑的是挑战主题，于是这一堆是打卡
│       └── 2026-09-24 第三次实验记录/
│           ├── entry.json
│           ├── note.md
│           └── 2026-09-24_实验_03.jpg
├── 未归类/                          没有题材、或者没有场景的记录
│   └── 2026-09-23 随手记一句/
└── 日记/                            另一个题材
    └── 每天/
```

**认目录的规则只有一条**（延续存储 v2 的"按结构识别，不按名字"）：
根下一级目录里带 `folder.json` 的 = **一个文件夹（内层，原"场景"）**；不带 `folder.json` 的 = **容器**；
**容器里既可以放文件夹，也可以直接放记录**（后者就是"未归类"）。

- 好处一：**"未归类"和"题材"是同一个机制**，不需要两套规则；用户把 `未归类` 改名成别的也照常认。
- 好处二：**根下直接摆文件夹 = 没有题材**，仍然读得出来 —— 老仓库、只想要"一锅装"的用户都照顾到了。
  （这是白送的容错，**不等于**恢复对 v1 布局的兼容：v1 仓库仍然直接拒绝。）
- 好处三：题材**可省**。新用户建一个仓库、建一个文件夹、开始记 —— 不必先想清楚题材怎么分。

## 3. 三层各管什么

| 层 | 管什么 | 形态 |
|---|---|---|
| **核心** | 记录怎么存、怎么改、有哪些能力（`vault/` + `useSceneData` + 公共件） | 代码，不动 |
| **内层文件夹**（现在的"场景"） | 这一堆记录怎么记：绑哪个主题、有哪些字段、媒体怎么命名、默认外观 | 已经是**纯数据声明** + 少数几个主题模块，本轮不动 |
| **题材**（新的一层） | 归类、打标签、在磁盘上成堆管理 | **目录**（可能再加一个标记文件，见 §7 第 1 条） |

**上一轮讨论的"记法"（随手记一句 / 认真写一篇 / 拍照打卡）这一轮不拆**：
它现在仍然是"内层文件夹绑的主题"决定的 —— `科研/论文笔记` 绑长文、`科研/实验打卡` 绑打卡。
好处是：**同一个题材里三种记法照样并存**（建三个内层文件夹就行），而记录层一个字都不用改。
将来真想做到"同一条记录也能换记法"（VISION §3.4 的升级链路），那才是动记录层的那一步，可以晚点单独做。

## 4. 这一版比我上一稿省在哪

| | 上一稿（动记录层） | 这一稿（外面套一层） |
|---|---|---|
| 磁盘 | `entry.json` 加 `kind`（记法标记） | 只多一级目录 |
| 核心 | 正文/记法要重新分层，"正文由题材声明"要退场 | 一行不动 |
| 记法 | 每条记录自己带 → 录入、列表、编辑器都要改 | 仍然是内层文件夹的属性 → 不用改 |
| 迁移 | 老记录要认默认记法 | 老仓库直接把根下的文件夹读作"没有题材" |
| 主要收益 | 一条记录能在简记/长文之间升级 | 归类、打标签、磁盘上好管 |

结论：**你的版本先做，我的版本留到真需要"同一条记录换记法"时再谈**（那一轮可以只加 `kind`）。

## 6. 一条目录层级做不到的事：多标签

目录是**单归属**：一条记录只能住在一个路径里，所以"这条记录既属于科研、又属于读书"这种
**多标签**，靠目录层级做不到。真要做多标签，得回到字段：`Entry.tags` **模型里早就有、现在没人用**，
配合一个"按标签筛选"的视图即可（不动磁盘布局）。

所以要分清你说的"方便打标签"是哪一种：

- **"把一堆记录归到一件事底下"** → 目录层级正合适（本提案）。
- **"一条记录能挂好几个标签"** → 目录做不到，得用 `entry.tags` + 筛选视图。

两个可以同时存在（题材是主归属，标签是横切）：这也符合 Obsidian 的用法（文件夹 + tag 并存）。

## 7. 待讨论

|---|---|---|---|
| 1 | 题材是不是"只是目录" | ① 纯目录（按结构识别，名字就是题材名）② 给个标记文件（`genre.json`：图标、颜色、顺序、封面）③ 用 `folder.json` 兼任 | **① 起步，②以后加**：先让目录层级跑起来；图标/顺序这类"用户数据"等真需要时再加标记文件（加文件是 `#[serde(default)]` 级别的改动） |

| 3 | 侧栏怎么排 | ① 题材 > 文件夹（两级树）② 只在文件夹行上显示题材名（平铺列表） | **①**：题材是你自己分的堆，应该一眼看见；平铺会把层级藏起来 |

| 5 | 已有的 v2 仓库怎么迁 | ① 硬切（按既有政策：不做兼容）② 给一个一次性动作："选几个文件夹 → 塞进一个题材" | **② 更省事**：不是兼容，而是**一个显式的整理动作**（用户自己按），Rust 里就是几次 rename |
