## 1. 目标布局（已确认）

```text
<用户选的目录>/
├── vault.json                      # 身份文件，+ "layout": 2
├── .framevault/trash/<entryId>/    # 删掉的记录挪这儿（撤销 = 挪回）
├── 未归类/                          # 固定容器：不属于任何场景的记录（见 §2.5）
│   └── 2026-09-22 早跑 3km/
└── 晨跑打卡/                        # 一级目录 = 场景（用户起的名，净化后）
    ├── folder.json                 # id / 主题绑定 / sceneConfig / 排序置顶
    └── 2026-09-22 早跑 3km/         # 二级目录 = 记录（创建日 + 标题）
        ├── entry.json              # id / 时间戳 / 标题 / fields / media[]
        ├── note.md                 # 正文（唯一真相）
        └── 2026-09-23_晨跑打卡_5公里_01.jpg   # 媒体：导入时按模板命名（§3.3）
```

对比 v1（`entries/<uuid>/entry.json`、`media/<uuid>/{orig.<ext>,meta.json}`）：目录名可读、
正文是 `.md`、媒体用有意义的名字 —— 对齐「开放普通文件」的初衷（PRD §12 第 6 条）。

## 2. 已拍板的语义

| 决定 | 结论 |
|---|---|
| 标题改了目录名跟不跟 | **跟随改名**：应用内改标题 / 改场景名时，同卷 `rename` 重命名磁盘目录（原子）。UI 方向：改名做成"点进去像编辑文本一样直接改"的就地编辑，不要按钮 + 弹窗流 |
| 绕开应用手动挪动 / 改名 | **磁盘为准**：归属从物理位置派生，扫描时跟着认。**手动改过的名字永久保留**（§3.5），系统不再用模板覆盖它 |
| 记录目录名里的日期 | **记录自身的创建日**（不是"这条按哪天算"的影像日）—— 补照片让影像日变化时，目录名不动 |
| 旧布局仓库 | **直接拒绝**，不做适配、不做迁移 |
| 无场景记录 | 根下固定容器 `未归类/`（§2.5） |
| 媒体文件名 | **导入时按模板生成**（VISION §3.5），不再是"照搬原始名"；只在导入那一刻定一次，之后永不改 |

### 2.5 「未归类/」的规则

- 它是**容器**，不是场景：**没有 `folder.json`**、不绑主题、不出现在主题注册表里。
- **按结构识别，不按名字识别**：根下一级目录里，有 `folder.json` 的 = 场景；**没有的 = 未归类容器**。
  这样用户把它改名成别的（或误建第二个）也照常认，符合「磁盘为准」。
- 记录归属派生：父目录是场景 → 该场景 id；父目录是未归类容器、或**直接摆在仓库根下** → `folderId = null`。
- 应用里显示成「未归类」分类；**不允许在应用内改名 / 删除**（删了，无场景记录就没地方去了）。
- `create_vault` 时预建这一个目录。

## 3. 命名规则（唯一出口：Rust 侧 `naming`）

### 3.1 净化（场景名 / 标题 / 媒体名共用）

非法字符 `\/:*?"<>|` 与控制字符剔除；Windows 保留名（`CON` `PRN` `AUX` `NUL` `COM1-9` `LPT1-9`，
含带扩展名的形态）加前缀规避；去掉尾部空格与点；长度截断（场景名、记录名各 ~80 字符，兜底 MAX_PATH）；
空名走兜底（记录用日期，场景用「未命名场景」）。**CJK 的 NFC/NFD 归一本轮不做**（见 §8 已知限制）。

### 3.2 目录名派生

- 场景目录名 = `净化(场景名)`
- 记录目录名 = `"{创建日} {净化(标题)}"`（标题为空时只留创建日）
- **净化后的名字就是名字本身**：`FolderMeta.name` / `Entry.title` 与磁盘目录名保持相等，
  所以不需要额外的"目录名字段"，也不会出现"界面上叫 A、磁盘上叫 B"。
  代价（明说）：标题里打 `/` 会立刻变成 `_` —— 与 Obsidian 文件名同款行为。

### 3.3 媒体文件名模板（VISION §3.5）

- 场景在 manifest 里声明（纯数据）：模板 + 回退；**核心提供默认模板**，不声明也能用。
- **模板由前端按 manifest 解析后、作为参数传给 `import_media`**，Rust 只做渲染 / 净化 / 去重。
  理由：第三方场景的 manifest 在插件包里，Rust 不该去读插件目录（VISION §3.9「一切皆插件」）——
  否则场景一旦插件化，这套命名就只有内置场景能用。
- v1 变量集：`{date}`（拍摄日，缺则导入日）、`{scene}`（场景名）、`{title}`（记录标题）、
  `{field:<key>}`（该场景声明可入名的字段，取不到就跳过）、`{n}`（同目录内序号）。
- 回退链（照 VISION §3.5）：取不到内容字段 → 场景级；没有场景 → 经典默认（日期 + 时间 + 地点）。
- 定完名之后：**只在导入那一刻命名一次**；用户之后手动改名不会被任何代码路径改回去（天然满足"不覆盖"）。
- 与 v2 原稿"用原始文件名"相反 —— 以本条为准。

### 3.4 撞名

同一目录内撞名一律加 ` (2)`、` (3)`…（场景、记录、媒体共用同一条规则），**绝不覆盖已有文件**。

### 3.5 手动改名的判定（"永久保留"怎么落地）

- 磁盘名为准：扫描时**不比对模板**，直接把磁盘上的目录名收进记录（`title` / `FolderMeta.name` 跟着它走）。
- 应用内改标题 → 用模板算新名 → 与当前磁盘名不同才 `rename`。
- 一旦磁盘名与"模板会算出的名字"不一致（说明用户手动改过），**该记录从此不再自动改名**：
  之后改标题只写 `entry.json`，不动目录名。判定不需要额外字段（磁盘名 vs 模板名比一下即可）。

## 4. 数据模型改动（`vault/model.rs`）

| 结构 | 改动 |
|---|---|
| `SCHEMA_VERSION` | `1` → `2`；`is_supported` 仍是等值判断 → v1 仓库被拒（这就是"不做兼容"的落点） |
| `Entry` | 新增 `day: String`（`#[serde(default)]`）：**创建日的本地日期**，前端在 `save_entry` 时给。没有它，Rust 没有时区就算不出目录名（从 trash 恢复时尤其需要）；正文不进 JSON；新增 `media: Vec<MediaMeta>`（`#[serde(default)]`，媒体元数据收进记录）；`deletedAt` 保留；新增 `sceneVersion: u32`（`#[serde(default)]`）——**为 VISION §3.10 的"场景版本管理 / 用户自定义数据结构迁移"留位**：将来要知道"这条记录是哪一版场景结构写的"，现在加成本近零，晚加只能靠 `updatedAt` 时间窗猜 |
| `note.md` | **不是字段**：`Entry.note` 用 `#[serde(skip)]`，读时从 `note.md` 填、写时写回 `note.md` |
| `FolderMeta` | `name` = 净化后的目录名（§3.2）；其余不动 |
| `MediaMeta` | 新增 `file: String`（磁盘上的实际文件名）；`name` 保留为**用户原始文件名**（展示用）；`id` / `hash` / 尺寸 / `takenAt` 保留；缩略图仍按 `id` 键存应用数据目录（改名不影响） |
| `VaultMeta` | 新增 `layout: u32`（`#[serde(default = "2")]`） |

## 5. 扫描与对账（磁盘为准）

- `list_folders`：扫根下一级，带 `folder.json` 的 → 场景（**不再有 `folders/` 这层**）。
- `list_entries`：根下一级（未归类容器 + 兜底：根下直接摆的记录目录）、以及每个场景目录下的记录目录；
  带 `entry.json` 才算记录，缺的忽略并 `eprintln` 打日志（沿用现在的"一个坏 JSON 不毁整次扫描"）。
- `list_media`：从各 `entry.json` 的 `media[]` 汇总（**不再扫 `media/`**）。
- 对账：磁盘多出的媒体文件 → 收养进 `media[]`；`media[]` 里有但磁盘上没有的 → 剔除。
- **宽容条款**：场景目录 / 未归类容器里出现我们不认识的文件或子目录（用户自己整理的、别的软件写的笔记…）
  一律**不动、不删、不报错**，只记日志 —— 为 §3.8 的 Obsidian 联动和手工整理留空间。
- **解析层不引入 id→路径缓存**（原稿提过）：每次按扫描定位。少一类"缓存过期"的 bug，且"磁盘为准"本就要重扫。

## 6. 写路径与原子性

`write_json_atomic`（tmp + rename，已在用）保留，新增 `write_text_atomic`（给 `note.md`，同样 tmp + rename）。
**一次保存的顺序：写 `note.md` → 写 `entry.json` → 最后 `rename` 目录**。
最坏情况是"内容已更新、目录名还是旧的"，下次保存自动收敛 —— 不会出现目录名新、内容半截的状态。

## 7. 删除与撤销

- 删除记录：整个记录目录挪进 `.framevault/trash/<entryId>/`，同时写 `deletedAt`（原稿的"保留字段"不变）。
- 撤销：按记录里的 `folderId` 挪回原场景（目录名按 §3.2 重算 + 去重）；原场景已删 → 回 `未归类/`。
  恢复只需要 `entry.json`（`day` + `title` + `folderId`），不需要额外元数据文件。
- 删除场景：**非空拒绝**（今天也拒绝，只是现在目录里装着记录，必须守住）。
- 顺手删掉 `create_vault` 里从未接线的 `.framevault/tombstones`（已确认全仓无第二处引用）。
